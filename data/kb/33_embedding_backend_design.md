# Embedding 后端与向量表示边界

## Embedding 表达语义邻近

Embedding 把查询和文本映射到固定维度向量，余弦距离可用于寻找语义相近内容。它适合处理同义改写和词面差异，但不是事实判断器。两个段落主题相似不代表其中一个真正回答问题，因此仍需要 BM25 互补和 rerank 精排。

## FastEmbed 本地推理

fastembed 后端使用本地 ONNX 模型生成向量，避免每次调用远程 API。首次使用通常需要下载模型，离线环境必须提前缓存。模型名称属于索引版本的一部分，换模型后旧向量不可继续比较，必须重建集合。

## 远程接口的契约

remote 后端调用 OpenAI 兼容 embedding HTTP 接口，发送 model 和 input 列表，并按响应 index 恢复顺序。它需要 URL、可选 API Key 和显式 timeout。返回向量数量必须与输入数量相同，否则应报错而不是截断后继续建库。

## Fake 后端只用于测试

fake embedding 使用词项哈希生成固定维度向量，不下载模型，也不需要密钥。相同文本得到相同向量，因此适合 CI 验证索引、查询和降级路径。它没有经过语义训练，不能用其 Hit@K 代表真实检索质量。

## 文档与查询使用同一空间

建库时调用 embed_documents，查询时调用 embed_query，但二者必须来自兼容模型和维度。若文档使用模型 A、查询使用模型 B，即使向量长度相同，坐标含义也可能完全不同。配置快照应同时记录 backend 和 model。

## 归一化与余弦距离

某些后端返回单位向量，某些只返回原始表示。Chroma 使用 cosine 空间时会按余弦距离排序，业务层再把距离转换为相似度展示。该分数只在同一通道和同一模型内有意义，不能与 BM25 原始分直接相加。

## 批量嵌入提高吞吐

建库应把多个 chunk 组成批次调用 embed_documents，减少模型初始化和网络往返。批次过大可能占用过多内存或触发服务限制，生产实现可进一步配置批大小。查询通常只有一条，使用 embed_query 更直接。

## 空文本与零向量

Loader 和 splitter 已过滤空文档，embedding 层仍应对空列表返回空结果。fake 后端遇到没有有效词项的字符串可能产生零向量，这类内容不具备语义比较价值。最安全的做法是在摄取阶段拒绝无意义 chunk。

## 模型下载失败属于通道故障

本地 ONNX 模型缺失或下载失败时，向量通道可以记录错误，由 pipeline 继续尝试 BM25。工具层不应因为向量失败就自行联网，是否使用 web_search 属于 Researcher 策略。通道错误必须进入 trace，避免静默降级掩盖部署问题。

## 维度错误应快速失败

同一 Chroma 集合一旦写入某个维度，再写另一维度向量会失败或不可比较。构建索引使用 reset 语义可以避免旧模型残留。远程接口若返回长度不一致，也应在入库前检测，不能等查询阶段才发现。

## 评测覆盖互补题型

语义改写题用于观察 embedding 是否能跨越表面用词，精确术语题通常更利于 BM25。混合检索的价值来自两者互补，不应只用包含文档标题的查询评测向量模型，那会让任务过于简单并产生天花板效应。

## 生产模型与测试后端分离

CI 固定 EMBEDDING_BACKEND=fake 保证无网络，正式报告则冻结 fastembed 或远程模型。两类运行可以共享相同 splitter 和 gold chunk，但原始结果必须记录后端，报告生成器不得把它们聚合成同一实验组。
