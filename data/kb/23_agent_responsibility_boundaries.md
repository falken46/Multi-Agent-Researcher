# Agent 职责边界与工具解耦

## Planner 只负责拆解

Planner 接收研究主题并产出可执行的子问题，不直接搜索网页，也不撰写最终结论。它的输出质量体现在覆盖范围和子问题独立性。若 Planner 同时完成检索，后续 Researcher 既无法替换检索策略，也很难单独测量规划对结果的影响。

## Researcher 负责证据获取

Researcher 消费子问题，先查询本地知识库，在证据不足时再联网，并将摘要与结构化引用写回状态。它不决定最终文章结构，也不应凭模型常识补全证据。研究节点的成功标准是提供可追溯材料，而不是生成一篇看似完整的文章。

## Critic 负责质量判断

Critic 根据明确评分锚点检查证据覆盖、结构和缺失方面，输出 quality_score、critique 与 missing_aspects。它不直接调用 Researcher，也不自己补写答案；条件边根据评分决定是否返工。这样评价规则可以单测，返工路径也保持在图层可见。

## Writer 负责整合表达

Writer 根据子问题、研究摘要、错误记录和引用生成 Markdown 报告。它不再执行搜索，因为写作阶段临时找资料会绕过 Researcher 的 trace 和降级策略。Writer 必须引用已有来源编号，不能把语言流畅当成证据充分。

## 工具只做 IO

web_search 和 kb_search 等工具负责输入校验、外部访问与结果规范化，不决定是否调用另一个工具，也不嵌入长 Prompt。联网降级属于 Researcher 的策略。如果工具看到低分就自行搜索网页，Agent 将无法解释路径，测试也无法隔离两种通道。

## Prompt 与执行代码分离

角色目标、语气和输出格式放入 Markdown Prompt，Python 保留加载、调用、解析和错误处理。这样修改行为约束不会制造大段代码差异，也便于审阅。短小的消息拼装可以留在代码中，但超过数行的系统说明不应硬编码。

## 结构化输出要有降级值

Planner 或 Critic 请求 JSON 时，模型可能返回代码围栏、缺字段或非法数字。解析层应清理常见包装，进行类型和范围校验，失败后给出中性结果并记录错误，而不是终止整个图。中性分数应触发保守路径，同时受返工上限保护。

## Agent 不直接互调

节点之间只通过 ResearchState 和 StateGraph 的边协作。直接从 Critic 导入 researcher_node 会形成隐藏调用栈，使 checkpoint 无法落在清晰边界，也让循环次数难以统计。依赖方向应从图指向节点，而不是节点彼此形成网状引用。

## 每个节点统一记录入口

节点入口日志至少包含角色名和输入摘要，trace 还应记录 node_start、node_end、耗时与状态。日志用于开发者阅读，trace 用于机器聚合。只打印整份状态既可能泄露长文本，也会制造噪声，应优先记录数量、标识和截断摘要。

## 异常边界由 Agent 捕获

工具遇到明确失败应抛出有语义的异常，调用它的 Agent 决定降级并写入 state.errors。若工具吞掉异常返回空列表，Researcher 无法区分“没有结果”和“通道损坏”；若 Agent 完全不捕获，单一外部错误又会摧毁已完成的其他分支。

## 节点测试使用依赖替身

单测 Agent 时应 Mock 统一 LLM 入口和工具，而不是访问真实网络。输入固定状态后断言局部更新、调用参数和错误分支。真实 API 测试单独标记 live，避免密钥和网络状况成为 CI 成败条件。

## 边界让替换成本可控

当搜索供应商、模型或向量库变化时，只需替换对应适配层，角色协议保持稳定。相反，如果 SDK 调用散落在每个 Agent 中，同一次迁移会同时修改策略、Prompt 和 IO。单一职责不是为了文件数量，而是为了把变化限制在正确位置。
