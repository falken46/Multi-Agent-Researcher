# Checkpoint 恢复语义与持久化边界

## Checkpoint 保存可继续执行的状态

LangGraph Checkpointer 在节点边界保存共享状态和下一执行位置。它解决的是“任务中断后从哪里继续”，而不是长期日志查询。恢复时应该重用稳定 thread_id，让框架找到对应快照；换一个标识会创建新任务，无法命中旧状态。

## thread_id 是执行身份

thread_id 应由请求显式提供或在任务开始时生成，并在 SSE start 事件中返回给客户端。它必须满足路径和数据库安全约束，不能直接使用任意用户文本。trace_id 标识一次可观测调用链，两者可能相关，但用途不同，不应因为名字都像 ID 就混用。

## None 输入表示继续而非新建

恢复已有 LangGraph 任务时，调用图通常使用相同配置并传入 None 作为新输入，表示从 checkpoint 的下一步继续。重新提交完整初始状态可能覆盖已保存进度或从头执行。API 层还应核对恢复请求中的主题与已保存主题一致，避免拿错线程。

## durability sync 的取舍

同步持久化要求状态写入完成后再开始下一步，可以降低进程崩溃时丢失最近进度的概率。代价是每个节点边界增加写入延迟。研究任务节点本身往往远慢于 SQLite 写入，因此演示项目优先可靠性是合理选择，但报告仍应记录真实端到端耗时。

## Checkpoint 不替代 trace

Checkpoint 面向恢复，可能被清理、覆盖或因 schema 升级迁移；trace 面向审计，保存调用、成本、降级和错误事件。用 checkpoint 计算指标会把运行状态结构绑定到评测脚本，也难以重建每次尝试。指标应来自 JSONL trace 或评测原始结果。

## SQLite 适合单机演示

SQLite 部署简单、无需额外服务，适合个人项目和单实例后端。它并不自动满足多副本、高写并发和跨地域容灾。生产场景应根据并发、备份与运维要求选择外部数据库，并确认所用 LangGraph saver 的事务和连接生命周期。

## 外部副作用需要幂等

Checkpoint 能保证图状态落盘，却无法与网页请求、邮件发送等外部副作用形成同一原子事务。恢复后节点可能重复执行，因此有副作用的工具需要请求幂等键或结果去重。纯检索重复执行通常只增加成本，但写操作重复可能造成真实损害。

## 连接生命周期覆盖流执行

异步 SQLite saver 的连接必须在整个 astream 期间保持打开，不能在返回生成器前退出上下文。SSE 流结束或异常后再关闭连接，既保证 checkpoint 可写，也避免资源泄漏。将连接创建在每个节点内部会增加开销并破坏事务边界。

## 恢复接口要区分状态

客户端可能请求恢复一个不存在、已经完成或仍在等待的线程。API 应给出可解释响应，而不是静默创建新任务。已完成任务通常直接返回结果或提示无需恢复；不存在的 thread_id 应明确报错，以免用户误以为系统恢复成功。

## Schema 升级影响旧快照

新增状态字段时节点应提供中性默认值，删除或改变字段语义则需要迁移策略。Checkpoint 数据不是永远兼容的黑盒。实验报告应记录代码版本和状态 schema 版本，否则同一 thread_id 在升级前后可能表现不同。

## 恢复测试必须制造中断

只测试数据库文件存在不等于恢复可用。有效测试应让图在中间节点暂停或故意中断，确认 checkpoint 中的下一节点，再用相同 thread_id 和 None 输入继续，最后验证昂贵的前置节点没有被重复调用。

## 清理策略与隐私

Checkpoint 可能包含用户主题、检索摘要和生成内容，需要保留周期、访问控制和删除机制。演示项目可以手动清理，但文档应承认这一点。把 SQLite 文件提交到 Git 会泄露运行数据，因此运行时 checkpoint 应进入忽略列表。
