# 检索通道降级、置信度与联网边界

## 两个本地通道独立执行

向量检索和 BM25 是并列候选生成器。pipeline 分别捕获它们的异常，将成功结果放入 channel_results，将失败原因放入 channel_errors。只要至少一个通道可用，就继续融合和返回，而不是把局部故障升级为整次研究失败。

## 建库也允许单通道成功

构建索引时，embedding 模型下载失败不应阻止 BM25 文件生成，反之亦然。BuildReport 分别给出 vector_count、bm25_count 和错误。只有所有已启用通道都没有建成时才抛出整体失败，否则用户仍能以降级能力运行。

## 工具不决定是否联网

kb_search 负责调用本地 pipeline 并规范化 hits 与 max_score，不根据分数自行访问网页。Researcher 拿到结果后结合阈值和通道错误决定 web_search。这个边界使工具保持 IO 属性，联网策略在 Agent 层可观察、可测试。

## 低分和故障是不同原因

本地通道正常但结果不相关属于 low_score，索引缺失或模型异常属于 kb_error。两者都可能触发 fallback，但 trace 应保存不同 reason。前者用于校准相关性阈值，后者用于发现部署和数据问题，运维动作完全不同。

## max_score 依赖排序阶段

向量相似度、BM25 原始分、RRF 分数和 cross-encoder 分数没有统一尺度。将最终结果中的最大 score 与固定阈值比较前，必须明确结果经过哪一阶段。否则关闭 rerank 的实验组可能因为 RRF 数值较小而全部联网，破坏对照。

## 阈值不是召回质量指标

高于阈值只说明系统选择信任本地候选，不保证其中包含 gold；低于阈值也不等于没有相关文档。阈值用于路由决策，Hit@K 和 MRR 才用于离线检索质量。把降级率当成准确率会产生错误结论。

## 联网结果追加而非覆盖

触发 web_search 后，本地 evidence 仍然可以保留，并与网页片段一起交给模型摘要。对于混合问题，本地材料可能回答设计原理，网页材料补充当前规范。直接丢弃本地结果会浪费已完成检索，也使引用来源不完整。

## 来源 origin 明确通道

Researcher 为证据标注 kb 或 web，Citation 同时保存 source 和 snippet。Writer 可以据此展示来源，评测也能统计本地与联网覆盖。只保存 URL 或文件名而没有 origin，会使相同字符串的来源类型难以判断。

## 单通道测试验证韧性

测试分别关闭 vector_search_enabled 和 bm25_search_enabled，确认另一通道仍返回结果；还应模拟索引损坏和 rerank 失败，断言错误被记录且返回降级候选。标准测试使用 fake embedding，不允许依赖网络或 API Key。

## 联网失败仍保留本地证据

如果低分触发 web_search，而网页服务随后超时，节点应记录该子问题错误，但不应删除已经取得的本地候选。是否能生成摘要取决于剩余 evidence。部分成功比把两个通道绑定成全有或全无更稳健。

## 评测分别观察路由和检索

检索微基准直接比较有序 chunk_id；路由评测观察 fallback 事件、reason 和阈值。两组指标可以关联分析，但不要通过日志正则间接推算。正式报告应列出阈值配置，并检查不同实验组的分数量纲是否兼容。

## 生产级降级还需熔断

个人项目的逐调用捕获可以展示基本韧性，大规模服务还需要全局熔断、健康检查、限流和恢复探测。若某通道持续故障，每个请求都先等待超时再降级会造成雪崩。承认边界比声称“已有完整高可用”更可信。
